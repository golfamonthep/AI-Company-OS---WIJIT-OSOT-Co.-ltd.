# Improvement Rules

## Improvement Lifecycle

1. Collect outcome, KPI, approval, collaboration, or human feedback.
2. Normalize feedback into structured learning data.
3. Analyze patterns and generate insights.
4. Create an improvement proposal.
5. Queue the proposal for human review.
6. Audit the proposal and decision.
7. Apply approved changes manually or through a future approved migration tool.

## Proposal Safety Rules

- Proposals are not source-of-truth changes.
- Proposals must include rationale, evidence, safeguards, and expected benefit.
- High-risk proposals require extra review.
- Blocked proposals must be rejected automatically when they target governance, permissions, core runtime, or audit systems.
- Rejected outputs should become cautionary examples, not automatic behavior changes.

## Approved Change Handling

Approved improvements may be converted into:

- skill quality checklist updates
- SOP notes
- workflow review checkpoint suggestions
- memory tags
- prompt refinement notes
- decision checklist updates

Approved improvements still require implementation in a controlled follow-up task.
